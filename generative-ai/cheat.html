The words

Generative AIAI that makes new text, images, code or audio
LLMLarge language model: predicts the next token, again and again
TokenA word or piece of one. 100 tokens ≈ 75 words
ParametersThe numbers a model learned (3B = 3 billion)
Context windowHow many tokens it can see at once
Temperature0 = predictable, ~1 = varied
HallucinationA confident, made-up answer
System promptYour hidden instructions: job, rules, tone
EmbeddingA list of numbers that captures meaning
RAGRetrieve notes, add them to the prompt, generate
Tool useThe model asks your code to run a function
AgentA model that uses tools in a loop until the job is done
Fine-tuningTraining a model more on your own examples
Prompt injectionText that tries to override your rules

Choosing a model

Closed (hosted)Most capable; pay per token; data goes to the provider
Open-weightFree to download; can run privately; check its licence
1–4B8 GB laptops: sorting, summaries, answers from notes
7–14B16 GB: better writing and reasoning

Test with your own questions, with known good answers, at temperature 0. Write test questions that can only be read one way.

Python: chat

import ollama
reply = ollama.chat(
    model="llama3.2",
    messages=[
      {"role": "system", "content": "Be brief."},
      {"role": "user", "content": "Hi!"}],
    options={"temperature": 0})
print(reply["message"]["content"])

Memory: append each user and assistant message to messages. Streaming: stream=True, then loop over the chunks.

Cosine similarity: closer to 1 = closer in meaning. RAG = 1. split notes into chunks · 2. embed them once · 3. embed the question · 4. take the top 3 · 5. put them in the system prompt · 6. show sources.

Responsible and safe

PrinciplesFairness · reliability and safety · privacy and security · inclusiveness · transparency · accountability
LayersModel · safety filters · system prompt · user experience
ThreatsPrompt injection (direct and hidden in documents) · jailbreaks · data leaks · poisoned data · too much power · overuse
DefencesLeast power · no secrets in prompts · check actions in code · a person approves · limits · logs
Red-teamTry to break it, record, fix, test again

From prototype to product

Idea → build → evaluate (quality, safety, speed, cost) → deploy to a few people → monitor → improve. Re-run your tests after every change of prompt, model or notes.

Fine-tune only after better prompts, a different model and RAG.
