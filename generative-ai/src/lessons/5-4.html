Let the model ask your code

A model can't check Brightside's bookings: it only knows what's in its training and its prompt. Tool use (also called function calling) fixes this. You describe some Python functions to the model; when it needs one, it replies with a request — "please run check_free_places with subject maths and day wednesday" — instead of an answer. Your code runs the function and sends back the result, and the model uses it to answer.

The model never runs anything itself. Your code decides what actually happens, which keeps you in control.

Tool use needs a model trained for it (the Ollama library marks them tools). This lesson uses qwen3:4b-instruct, which you pulled in Module 2.3.

The tools

module-5/tools.py (the first part)

"""Tool use: the model asks our code to look things up, then answers with the result."""
import datetime
import sys

import ollama

MODEL = sys.argv[1] if len(sys.argv) > 1 else "qwen3:4b-instruct"  # or: python tools.py llama3.2

# Pretend booking system: free small-group places per subject and day
FREE_PLACES = {
    ("maths", "monday"): 0, ("maths", "wednesday"): 2, ("maths", "saturday"): 1,
    ("english", "tuesday"): 3, ("english", "thursday"): 0,
    ("science", "wednesday"): 1, ("science", "saturday"): 4,
}


def check_free_places(subject: str, day: str) -> str:
    """Check how many free small-group places there are for a subject on a day of the week.

    Args:
        subject: maths, english or science
        day: a day of the week, like wednesday

    Returns:
        How many places are free
    """
    if not isinstance(subject, str) or not isinstance(day, str):
        return "Error: give one subject and one day per call."
    places = FREE_PLACES.get((subject.lower(), day.lower()))
    if places is None:
        return f"There is no {subject} group on {day}."
    return f"{places} free place{'' if places == 1 else 's'} in {subject} on {day}."


def todays_date() -> str:
    """Get today's date and day of the week.

    Returns:
        Today's date, like Monday 1 February 2027
    """
    today = datetime.date.today()
    return f"{today:%A} {today.day} {today:%B %Y}"

The Ollama library reads each function's name, type hints and docstring and turns them into a description the model sees. That's why the docstrings explain each argument: they're part of the prompt. FREE_PLACES stands in for a real booking system.

The loop

module-5/tools.py (the rest)

TOOLS = {"check_free_places": check_free_places, "todays_date": todays_date}

question = input("Ask about bookings: ")
messages = [
    {"role": "system", "content": "You answer booking questions for Brightside Tutoring. "
                                  "Use the tools to check places; never guess numbers."},
    {"role": "user", "content": question},
]

response = ollama.chat(model=MODEL, messages=messages, tools=list(TOOLS.values()),
                       options={"temperature": 0})

while response["message"].get("tool_calls"):
    messages.append(response["message"])
    for call in response["message"]["tool_calls"]:
        name = call["function"]["name"]
        args = call["function"]["arguments"]
        try:
            result = TOOLS[name](**args)
        except Exception as error:  # a wrong tool name or arguments: tell the model, so it can try again
            result = f"Error: {error!r}. Check the tool name and arguments and try again."
        print(f"[tool] {name}({args}) -> {result}")
        messages.append({"role": "tool", "content": result, "tool_name": name})
    response = ollama.chat(model=MODEL, messages=messages, tools=list(TOOLS.values()),
                           options={"temperature": 0})

print()
print(response["message"]["content"])
  1. tools= passes the functions to the model
  2. If the reply has tool_calls, run each one with its arguments, and add the result to the conversation as a tool message
  3. Ask the model again, with the results. Repeat until it replies with text
  4. If a call fails, send the error back instead of crashing, so the model can fix its request

Not every model is good at this

Ask about bookings: Are there any free maths places on Wednesday or Saturday?
[tool] check_free_places({'day': ['wednesday', 'saturday'], 'subject': 'maths'}) -> Error: give one subject and one day per call.

I can try again with a specific day and subject.

For Wednesday, here are some free maths places:

* Local library: They often have free maths classes or study groups for adults.
* Community centre: Many community centres offer free maths classes or workshops for adults.
...

It sent both days as a list, which the function doesn't accept. Thanks to the check, it got a clear error instead of the program crashing. But instead of trying again, it invented a list of libraries and community centres. This is why you test tool use with the model you'll actually use, and why the tool's code — not the model — checks its inputs.
