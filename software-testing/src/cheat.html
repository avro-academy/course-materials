What testing is

Checking software does what it should, and finding where it doesn't, before real people rely on it.

  • Testing shows bugs are there; it can't prove there are none
  • You can't test everything: choose wisely
  • Test early: bugs found in planning are cheapest
  • Bugs cluster: where there's one, look for more

Testable requirements

❌ "loads quickly"✅ "within 2 s on 4G"
❌ "valid names"✅ "2–40 letters, spaces, - and '"

Ask about gaps early: past pickup times? accents like Zoë? curly apostrophes?

Test design techniques

Equivalence partitions: one value from each group (too small, valid, too big, not a number).

Boundary values: test each edge and just outside it.

Quantity 1–100 ✗ · 1 ✓ · 10 ✓ · 11 ✗
Notes ≤ 200199 · 200 · 201

Decision tables: one column per combination of conditions; each column is a test case.

Exploratory testing

Explore     the discount code
with        different codes and orders of actions
to discover whether the total is ever wrong
  • Time-box: 30–90 minutes, no interruptions
  • Notes as you go: time · tried · happened · bug/question
  • Debrief: write up bugs, send questions, plan next session
  • Pair testing: one drives, one suggests

Heuristics

  • Goldilocks: too small, too big, just right
  • Zero, one, many
  • Add, change, remove (in different orders)
  • Interrupt it: reload, Back, double-click
  • Follow the money: check every total
  • Naughty inputs: O'Brien, Zoë, spaces, 😀, long pastes, <b>hello</b>

Severity = damage (tester). Priority = how soon to fix (team). They don't always match.

Reproduce and isolate

  • Reload and follow your steps again; say how often ("3 of 5")
  • Remove steps until it stops; try other items, sizes, browsers
  • Screenshot: Win+Shift+S · Cmd+Shift+4. Video: Snipping Tool · Cmd+Shift+5
  • Never use real personal details in test data
New → Open → Fixed → Retest → Closed
                       ↘ Reopened

Accessibility checks

  • Keyboard only: Tab, Shift+Tab, Enter, Space, arrows. Visible focus? Logical order?
  • Labels: click the label: does the cursor jump into the field?
  • Zoom 200% and contrast; colour never the only signal
  • Tools: Lighthouse, axe DevTools, WAVE (they find only some problems)
  • Screen readers: NVDA, Narrator, VoiceOver, TalkBack

Australia: Disability Discrimination Act; WCAG level AA.

Security mindset

  • Type <b>test</b> in every field; it should show exactly as typed (bold = HTML injection / XSS risk)
  • Anything checked only in the browser can be bypassed: the server must check again
  • Only test what you're allowed to; report real problems privately

Test plan

In scope · out of scope · approach · environments · risks · entry and exit criteria · schedule · deliverables.

Risk = likelihood × impact. Test the high-risk areas first and deepest.

Regression and reporting

  • Retesting: is this bug fixed?
  • Regression: did the fix break anything else?
  • Smoke test: 5 minutes; fails → send it back
  • Summary report: what was tested, results, open bugs, your recommendation

Agile: Given / When / Then

Given my order has a $9.50 toastie
When I apply the code student10
Then the discount is $0.95 and the total is $8.55

Help write acceptance criteria before work starts ("shift left"). Talk early, be specific and kind.
