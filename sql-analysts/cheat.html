The shape of a query

SELECT   columns, calculations
FROM     table
WHERE    row filter
GROUP BY groups
HAVING   group filter
ORDER BY sort
LIMIT    n;

Written in that order. Runs as FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT, so a SELECT alias works in ORDER BY but not in WHERE.

Look first

SELECT * FROM orders LIMIT 5;
SELECT COUNT(*) FROM customers;
SELECT DISTINCT category
FROM products;
SELECT product_name,
       list_price - unit_cost AS margin
FROM products
ORDER BY margin DESC;

Summarise

SELECT category,
       COUNT(*) AS products,
       ROUND(AVG(list_price), 2)
         AS avg_price
FROM products
GROUP BY category
HAVING COUNT(*) >= 6
ORDER BY avg_price DESC;

COUNT(*) rows, COUNT(col) non-NULL values, COUNT(DISTINCT col) different values. SUM AVG MIN MAX skip NULLs. Every SELECT column is grouped or aggregated.

CASE: your own groups

SELECT CASE
         WHEN list_price < 50
           THEN 'Under $50'
         WHEN list_price < 150
           THEN '$50-$149'
         ELSE '$150 and over'
       END AS price_band,
       COUNT(*) AS products
FROM products
GROUP BY price_band;

Count a condition: SUM(CASE WHEN x THEN 1 ELSE 0 END)

Joins

SELECT o.order_id, c.first_name
FROM orders AS o
JOIN customers AS c
  ON c.customer_id = o.customer_id;

-- customers who never ordered
SELECT c.customer_id
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;

JOIN keeps matches only. LEFT JOIN keeps every left row (NULLs where nothing matches).

Fan-out: the join trap

Joining orders to order_items repeats each order once per item, so SUM(shipping_fee) counts shipping again for every item. Check with COUNT(*) against COUNT(DISTINCT order_id). Fix: summarise each table first (CTE), then join.

Dates (SQLite)

strftime('%Y-%m', order_date)  -- 2025-05
strftime('%m', d)  -- month 01-12
strftime('%w', d)  -- weekday 0=Sun
date(d, '+30 days')
julianday(a) - julianday(b) -- days

Store dates as YYYY-MM-DD text so they sort and compare correctly.

Subqueries and CTEs

SELECT product_name, list_price
FROM products
WHERE list_price >
  (SELECT AVG(list_price) FROM products);

WITH items AS (
  SELECT order_id,
         SUM(quantity * unit_price)
           AS items_total
  FROM order_items
  GROUP BY order_id
)
SELECT ROUND(AVG(items_total), 2)
FROM items;

Window functions

RANK() OVER (PARTITION BY category
             ORDER BY list_price DESC)
SUM(revenue) OVER (ORDER BY month)
LAG(revenue) OVER (ORDER BY month)
RANK1, 2, 2, 4
DENSE_RANK1, 2, 2, 3
ROW_NUMBER1, 2, 3, 4

Top N per group: ROW_NUMBER in a CTE, then WHERE n <= 2. Change %: 100.0 * (x - LAG(x)) / LAG(x)

Traps

  • 7 / 2 is 3: use 7 / 2.0 or CAST(x AS REAL)
  • NULL is not 0: missing shipping isn't free shipping
  • Text matches are exact: UPPER(TRIM(x))
  • Filter status: delivered orders for revenue

Check new data

  • Row count as expected?
  • Duplicates: GROUP BY LOWER(TRIM(email)) HAVING COUNT(*) > 1
  • NULLs: COUNT(*) - COUNT(col)
  • Spellings: GROUP BY text columns, fix with CASE
  • MIN/MAX of numbers and dates

Clean in a CTE at the top, not in the original data.

Investigate a change

1 Confirm it. 2 Break it down (category, state, channel). 3 Find where it's concentrated. 4 Ask the people who know why. 5 Answer in plain words: lead with the answer, round the numbers, say what's included.
