Finding things

find /var/log -size +1M     # bigger than 1 MB
grep -i "flat white" file   # lines containing it

grep options: -i any case, -v lines that don't match.

Users and permissions

id                          # who am I, which groups
sudo adduser sam            # new account
sudo groupadd cafeteam
sudo usermod -aG cafeteam sam   # -a = add, don't replace!
sudo -iu sam                # act as sam
sudo deluser --remove-home sam
-rwxr-x---type, owner, group, others: r read, w write, x run/enter
755 rwxr-xr-xscripts, folders others may enter
644 rw-r--r--normal files
600 rw-------private: keys, passwords
770 rwxrwx---shared folder for a group
chmod +x backup.sh          # make runnable
chmod g+w f · chmod o-r f   # letters work too
sudo chown root:cafeteam /srv/cafe-shared

r=4, w=2, x=1. Least privilege: only the access each person and program needs.

Shell scripts

#!/bin/bash
set -euo pipefail           # stop at the first error
name="${1:-there}"          # 1st argument, or a default
echo "Hello, $name! It's $(date +%A)."
if [ "$(date +%H)" -lt 12 ]; then
  echo "Morning"
else
  echo "Afternoon"
fi
for item in "Flat white" "Latte"; do
  echo "$item"
done
tar -czf "backup-$(date +%F).tar.gz" cafe

Run with ./script.sh after chmod +x. Quote "$variables". Test a backup: tar -tzf file.tar.gz.

Software and services

sudo apt update && sudo apt upgrade
sudo apt install -y nginx · apt search word
ps aux · top · htop         # what's running
kill PID · kill -9 PID      # stop · force
systemctl status nginx
sudo systemctl restart|reload|enable nginx
journalctl -u nginx -n 20   # a service's log
sudo nginx -t && sudo systemctl reload nginx

Website files: /var/www/html. Settings: /etc. Logs: /var/log (nginx/access.log, auth.log).

SSH and keys

ssh-keygen -t ed25519 -C "sam laptop"
# put the .pub key in ~/.ssh/authorized_keys (700/600)
#   or: ssh-copy-id sam@SERVER (password logins on)
ssh sam@192.168.64.5
scp file sam@host:/path/ · scp host:/path/file .
# ~/.ssh/config
Host cafe
  HostName 192.168.64.5
  User sam

The private key never leaves your computer; protect it with a passphrase.

Securing a server

sudo ufw allow OpenSSH
sudo ufw allow 'Nginx HTTP'
sudo ufw enable · sudo ufw status
# /etc/ssh/sshd_config.d/99-cafe.conf
PasswordAuthentication no
PermitRootLogin no
AllowUsers sam ubuntu
sudo sshd -t &&
  sudo systemctl reload ssh
sudo apt install fail2ban

Update often, keys not passwords, firewall only what's needed, least privilege, backups you've tested, read the logs.
